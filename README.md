# 極速魔王挑戰

HTML5 網頁遊戲，使用原生 HTML、CSS、JavaScript 開發。

開發規格以 GAME_DESIGN.md 與 CODEX_TASKS.md 為準。

## 目前進度

已完成第 1–5 批：戰鬥原型、跨裝置視覺樣板、完整招式與五王占位演出、教學與暫停／退出流程，以及音效、評價、設定與本機排行榜。具備 16 招逐王解鎖、限制式抽招、五王連戰、四種成功動作、連擊傷害、失誤／超時、回血、自動換王、死亡重開及終焉魔王單次狂暴。

主畫面可選教學或挑戰模式。每局首次教學獨立重設，確認後才開始正常預告與倒數；暫停、分頁離開及視窗調整皆保留原局，由玩家手動恢復。退出需確認，取消後維持暫停。勇者、五王、狂暴角色及五戰場已使用新半寫實美術，共 21 張主要圖片；圖片載入失敗會安全降級。字體本機載入，戰鬥與文字特效受暫停及降低特效設定控制。學生體驗平衡、使用者美術確認、實體裝置與遠端部署仍待驗收。

提供程式合成的戰鬥／介面短音效，沒有背景音樂。設定可調音效開關、0–100% 音量及降低特效；預設音量 70%，初次使用依系統減少動態偏好設定降低特效。設定可從主畫面、暫停頁與結算頁進入，調整後不自動恢復戰鬥。

兩種模式均顯示 SSS～C 評價；只有挑戰模式五王通關可輸入 1–12 字暱稱入榜（以 Unicode 字元計數，去除前後空白）。本機保留前 20 名，排序為評價、未四捨五入正確率、有效戰鬥時間、較早完成；同名可保留多筆，清榜需再確認。儲存失敗會明確提示，保留當次結算與本頁暫存紀錄。

角色姿態、錨點與素材入口位於 `data/visuals.js`，來源與錨點見 [素材說明](assets/README.md)。21 張已製作並整合，實機與使用者美術確認待完成。

## 本機開發

需要 Node.js 22 以上（測試工具）與 Python 3（靜態伺服器）。網站本身不需建置或安裝套件。

```sh
npm start
```

從儲存庫根目錄執行，使用瀏覽器開啟伺服器的 8000 埠。ES modules 需透過 HTTP 載入，不能直接以 `file://` 開啟 HTML。

```sh
npm run verify
npm run simulate
```

選用瀏覽器驗收：環境需已提供 Playwright 與 Chromium，再執行 `node tests/browser.mjs`（戰鬥流程）、`node tests/visual-browser.mjs`（動畫與尺寸）、`node tests/boss-browser.mjs`（五王、解鎖與狂暴）、`node tests/lifecycle-browser.mjs`（教學、模式、暫停、退出與重玩）、`node tests/score-browser.mjs`（音效、設定、評價、排行榜與失敗降級）。可用 `CHROMIUM_PATH` 指定瀏覽器、`BOSS_RUSH_TEST_URL` 指定伺服器；截圖預設輸出至 `/tmp/boss-rush-validation`、`/tmp/boss-rush-visual-validation`、`/tmp/boss-rush-boss-validation`、`/tmp/boss-rush-score-validation`。新增 `node tests/stress-browser.mjs` 驗證八種活動階段及 200 次新局／退出。Playwright 僅用於驗收，不是網站依賴。

## GitHub Pages

網站使用原生靜態檔案與相對資源／模組路徑，可放在 `/boss-rush/` 子路徑下。

待使用者授權推送後，可在 GitHub 的 **Settings → Pages → Build and deployment** 選擇 **Deploy from a branch**、`main`、`/ (root)`。根目錄已加入 `.nojekyll`，不需要 bundler 或自訂 Actions 工作流程。此處記錄部署方式，不表示已啟用或發布 Pages。

CSS、入口 JS、模組及占位素材引用使用 `v=0.6.0` 快取版本；後續變更須同步更新相關引用。

各批細節、範圍限制與檢查紀錄見 [DEVELOPMENT.md](DEVELOPMENT.md)。

## 本機資料與音效

設定與排行榜分別使用 `boss-rush.preferences.v1`、`boss-rush.leaderboard.v1`。清榜不影響設定，不儲存進行中的戰鬥或跨局教學清單。本機資料可被使用者修改，沒有防作弊或跨裝置同步；同時開多個分頁不保證合併寫入。

音效程式位於 `effects/sound.js`，短音由 Web Audio 合成，不需外部音檔授權或下載。音訊未獲允許、不支援或播放失敗時，遊戲仍可判定及結算。關閉音效、音量歸零、暫停或退出會停止當前短音，不排隊延後播放。

## 第六批驗收與平衡發現

`npm run verify` 包含語法、55 項邏輯測試及靜態部署檢查；`npm run simulate` 執行八種可重現模型、預設每模型 1000 局。可用 `BOSS_RUSH_SAMPLES` 調整樣本數（1–10000）。報告見 [平衡模擬](reports/balance-v0.6.0.md) 與 [完整數據](reports/balance-v0.6.0.json)。

全 PERFECT／GREAT／GOOD 逐王總命中為 49／52／56；完整通關中位數約 128／165／240 秒。97%／90%／80%／65% 正確率模型的通關率為 98%／27.5%／0.1%／0%；這些是明列反應分布的假設模型，不是學生體驗統計。

原 0.6.0 HP 預算讓通關最多承受 8 次失誤，因此 B（通關且正確率低於 80%）無法達成。未自動修改任何數值或評價規則；容錯、B 門檻與一般 3–5 分鐘體驗仍需確認。

七種尺寸、六套 Chromium 瀏覽器驗收與 `/boss-rush/` 子路徑檢查通過。Firefox／WebKit 未安裝、實體手機及 21 張正式美術尚未驗收。GitHub main 可讀，但 Pages 設定 API 回覆 Forbidden；未確認遠端 Pages 啟用狀態、未提交／推送／發布。細節與發布前待辦見 [第六批驗收](reports/acceptance-v0.6.0.md)。

容錯探索已另比較五組參數、共 40000 局；當時正式遊戲仍保留原規則。詳見 [候選方案比較](reports/balance-candidates-v0.6.0.md)。只降低扣血會讓更多慢速／失誤樣本存活，80% 模型若多數通關，其通關中位時間可能超過 3–5 分鐘目標，仍需先確認設計方向。

## 0.9.2 iPhone 聲音輸出

依實機無聲回報，iPhone／iPad將合成音訊橋接至原生媒體播放器，支援時設定播放audio session；媒體play與AudioContext.resume都在使用者手勢內直接呼叫。設定顯示版本與音訊狀態，方便確認新版與播放權限。60單元測試及Chromium實際媒體串流輸出／試聽／靜音重啟通過；實體iPhone是否出聲仍待確認。見[0.9.2驗收](reports/acceptance-v0.9.2.md)。

## 0.9.3 音訊啟動重試

修正首次pointerdown的resume/play若一直等待時，後續click沿用待完成Promise而無法重試的路徑。每次使用者手勢可重新啟動，新增touchend啟動，舊請求不能覆蓋新的結果。設定狀態沿用現有畫面更新迴圈即時顯示等待／成功／失敗及錯誤名稱，未新增計時器。版本及所有資源引用同步0.9.3。

61項測試通過，含首次resume未完成、第二次手勢成功的重現與回歸測試；Chromium實際手機媒體輸出／試聽／靜音重啟通過。發布清單與雜湊通過。此缺陷可重現，但無實體iPhone，不能確定它是使用者無聲的唯一原因；尚需新版實機結果。

## 0.9.4 音效持續鳴叫修正

依實機間歇性狂響回報，短音改用有限PCM AudioBuffer、loop=false、長度最多0.455秒，自然結束；保留不支援buffer環境的oscillator降級，但尾端明確設gain=0。配樂停止取消loop且stop/disconnect分開執行，stop失敗仍切斷輸出。停止同步靜音並pause手機HTMLAudio；遲到的啟動Promise不得重新開啟已停止的播放器。切背景、blur及pagehide直接停止音訊。修正首頁每影格stop使試聽被切斷，改為只在進入首頁／暫停時停止。

63項單元測試全過，包含非循環短音、尾端靜音、首頁100影格保留試聽、停止手機輸出及遲到解鎖不復播。Chromium手機媒體輸出／試聽／靜音重啟、四尺寸首頁配樂暫停恢复，以及score-browser音訊／儲存／失敗降級／CPU節流通過。同步版本0.9.4，build及發布清單雜湊通過；實體iPhone間歇性問題仍需使用者驗收，不能宣稱唯一原因已確定。

## 0.9.6 切分頁後音訊恢復

背景visibilitychange、pagehide與blur會停止聲音並標記音訊需要重建；回到頁面後的下一次使用者手勢才清理舊播放器、停止MediaStream音軌、斷開增益與關閉舊AudioContext，再建立新context／媒體輸出。原本resize仍只暫停，不做輸出重建。戰鬥依舊手動恢復，不重設HP、回合、成績或音樂偏好。舊啟動Promise以context身分與attempt序號拒絕覆蓋新輸出，不新增計時器。

64單元測試通過，包含背景後重建、舊音軌釋放、遲到舊請求不得影響新輸出。Chromium實際媒體串流連續五次pagehide／返回試聽重建成功，舊播放器srcObject清空、新音軌live；三尺寸音樂開關與偏好保留通過，靜態／build／發布清單雜湊通過。模擬iPhone辨識及合成生命周期事件不等同實體Safari切分頁；仍需使用者確認0.9.6實機音訊是否恢復。
