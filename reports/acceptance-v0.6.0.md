# 第 6 批驗收紀錄｜v0.6.0

## 結論

功能與自動驗收通過；**學生體驗平衡、正式美術、實體裝置與遠端 Pages 發布尚未驗收**。本批保留 HP、傷害、回血、時限、抽招權重及動畫節奏，不將自動模型等同真人體驗。

## 平衡待確認

[模擬報告](balance-v0.6.0.md) 與 [JSON](balance-v0.6.0.json) 保存模型、樣本數、種子、時間分布、逐王命中與成敗範例。90% 模型僅 27.5% 通關、80% 僅 0.1%；不能據此聲稱適合目標學生。全 GREAT 約 2:45、全 GOOD 約 4:00；3–5 分鐘是一般目標，快速熟練玩家可短於此範圍。

B 評價無法在現行規則下達成：最多 180 HP、每次失誤至少 −20，通關最多 8 次失誤；14100 Boss HP／最高 360 傷害至少 40 次正確，正確率保守下界約 83.33%。需決定是否接受此限制，或另行批准容錯／評價調整；本批未變更規則。

## 正式發布前待辦

1. 確認目標學生容錯與 B 評價處理方式；如要調整核心規則，先更新 GAME_DESIGN 與測試，再重新驗收。
2. 21 張正式素材全部待製作／授權與替換；目前 12 張原創 SVG 只作占位，正式完成數為 0。
3. 實體手機直／橫放、瀏海及底部安全區、音訊策略、實際音質與效能；Firefox／Safari 實機亦尚未驗收，環境未安裝 Firefox／WebKit。
4. 使用者明確授權提交／推送後，核對全部工作區變更，將程式、測試、報告、規格與 `.nojekyll` 提交至指定 GitHub main。此時遠端 main 仍是 `b2e098524899ee2c92e163eaa9d942f5d5f9b759`，目前開發分支是 `work`，本批沒有提交／推送。
5. 在 repository 的 Settings → Pages 選 Deploy from a branch、main、/ (root)，等待部署後檢查正式頁面、所有版本化資源及手機操作。GitHub Pages 設定 API 實際回覆 `Forbidden`，無法由本次工具確認遠端是否已啟用；不能把本機子路徑通過寫成正式發布通過。

本機排行榜不跨裝置同步、不防作弊，並行分頁不保證合併寫入；這些是既定本機方案的限制。
